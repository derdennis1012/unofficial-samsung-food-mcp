For developers: All {{TOTAL}} tools CLI reference HTTP API Other MCP clients How it works

Looking is free. Changing asks first.

Each of the {{TOTAL}} tools is labelled as read-only, write or destructive, so your AI client knows which calls only look and can ask you before anything in your account changes.

{{READ}} read-only
Plans, lists, pantry, recipes, nutrition.
{{WRITE}} write
Add meals, items, recipes.
{{DESTRUCTIVE}} destructive
Remove, clear or replace.
  • Your login stays on your machine, in ~/.samsung-food with owner-only permissions, and renews itself while you use it.
  • No telemetry. It talks to Samsung Food and nothing else.
  • The HTTP API stays local: it binds to 127.0.0.1, needs an API key, and --read-only drops every write tool.

Cooking in one command.

  1. 1Run npx unofficial-samsung-food-mcp setup. It needs Node.js 20 or newer.
  2. 2Log in on the page that opens: one bookmark button on app.samsungfood.com. Samsung has no OAuth, so this hands your session over once.
  3. 3Pick your clients (Claude Code, Claude Desktop, Cursor, VS Code), restart, ask for dinner.

Before the npm release: clone, npm install, then node bin/sf.js setup --local. No install at all: the hosted connector (closed beta). Full walkthrough

What it can’t do (yet).

  • No search across all recipes.Search covers your saved recipes. Discover, similar and import bring in new ones.
  • Meals don’t scale.Servings are set when ingredients go to the shopping list.
  • Some sites block imports.Bot protection stops the scraper; you get an error, not a guess.
  • Logins last 14 days.They renew while you use it. After a longer break, run sf login again.
